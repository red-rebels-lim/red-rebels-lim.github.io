## 6. Tooling gotchas recorded for future runs

- `flutter test integration_test` leaves the **test APK** installed — its `main()` waits for a driver and sits on the splash forever. `run-suite.sh` now rebuilds + reinstalls the product APK before device-level passes.
- iOS: `simctl spawn defaults write` doesn't reach the app container; write `Library/Preferences/<bundle-id>.plist` in the container + `killall cfprefsd` (app must have run once first — seeding before first launch white-screens the app).
- Don't run 2+ emulators/simulators concurrently with builds on this machine — emulators get killed / sims white-screen under pressure. One device at a time.
- `avdmanager` needs `JAVA_HOME=/opt/homebrew/opt/openjdk@21`.
- Standalone `simctl launch` of a **debug** Runner.app can white-screen (engine idles without a host; process alive, no first frame) — drive iOS via `flutter test -d <udid>` / `flutter run`. Release builds unaffected.
- The Jul 27 emulator deaths were qemu **crashes** (`~/Library/Logs/DiagnosticReports/qemu-*.ips`) — run one emulator at a time on this machine.
- Emulators launched from a tool shell die with their parent — keep the launching script alive (see `scratchpad/boot_one_avd.sh` pattern) or launch from the desktop.
